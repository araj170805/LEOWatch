# Orbital Guardian

Space Situational Awareness · satellite & debris tracking · SGP4 orbital
propagation · conjunction screening · heuristic risk ranking · AI/RAG copilot.

```
.
├── backend/     FastAPI + SGP4 + conjunction engine + RAG  →  deploy to Render
│   ├── app/           application code (routers, orbital/, rag)
│   ├── knowledge/     curated RAG markdown knowledge base
│   ├── data/          TLE cache + RAG embedding cache (runtime)
│   ├── tests/         standalone test suites
│   ├── requirements.txt
│   ├── render.yaml is at repo root
│   └── .env.example
└── frontend/    React 18 + Vite + CesiumJS + Tailwind      →  deploy to Vercel
    ├── src/
    ├── public/
    ├── vercel.json
    └── .env.example
```

## Local development

### Backend (port 8000)
```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # then fill in keys (optional — see below)
uvicorn app.main:app --reload --port 8000
```
or run `backend\run_backend.bat`.

### Frontend (port 5173)
```powershell
cd frontend
npm install
npm run dev
```
or run `frontend\run_frontend.bat`. Vite proxies `/api` → `http://127.0.0.1:8000`,
so no frontend env vars are needed locally.

### Tests
```powershell
cd backend
.\run_tests.ps1
```

## Is a database required?

**No — not for the core product.** Everything a guest can do runs with **zero
database**: catalog, object intelligence, SGP4 trajectories, conjunction
screening, TCA, risk scoring, and the AI/RAG copilot.

A database is only touched by **two features**: user accounts (`/auth/*`) and
**saved analyses / history** (`/history`).

| Setup | `DATABASE_URL` | Result |
|-------|----------------|--------|
| Default (nothing set) | *unset* | Bundled **SQLite** file `backend/orbital_guardian.db`. Zero config. Accounts/history work but are **wiped on redeploy** on Render (ephemeral disk). Fine for a demo. |
| Persistent | `postgresql://…` | Use Render's free PostgreSQL. Accounts/history survive restarts. `psycopg2-binary` is already in `requirements.txt`. |

So: run it with **no database** and guests get the full SSA experience. Add
**Render PostgreSQL** only if you want logins to persist between deploys.

## Deployment

### Backend → Render
1. Push this repo to GitHub.
2. Render → **New → Blueprint**, pick the repo. `render.yaml` (repo root,
   `rootDir: backend`) provisions a free Python web service:
   `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, health check `/health`.
3. Set env vars in the Render dashboard (all optional except `CORS_ORIGINS`):
   - `CORS_ORIGINS` = your Vercel URL, e.g. `https://orbital-guardian.vercel.app`
   - `GEMINI_API_KEY` (+ keep `GEMINI_MODEL=gemini-2.0-flash`) — enables AI
     explanations; the app runs fine without it (deterministic fallback).
   - `DATABASE_URL` — only if you added a Render PostgreSQL instance.
   - `JWT_SECRET_KEY` — auto-generated by the blueprint.
4. Note the service URL, e.g. `https://orbital-guardian-api.onrender.com`.

### Frontend → Vercel
1. Vercel → **Add New → Project**, import the repo, set **Root Directory =
   `frontend`**. Framework preset: Vite (auto-detected). `vercel.json` handles
   SPA routing.
2. Add one env var:
   - `VITE_API_URL` = your Render URL (no trailing slash), e.g.
     `https://orbital-guardian-api.onrender.com`
3. Deploy. Then go back to Render and make sure `CORS_ORIGINS` contains the
   final Vercel domain.

## Technology stack
- **Frontend**: React 18, React Router, CesiumJS, Framer Motion, TailwindCSS, Vite
- **Backend**: FastAPI, `sgp4`, SQLAlchemy, Pydantic, bcrypt + JWT auth
- **Orbital data**: CelesTrak GP/TLE elements (latest available — *not* live telemetry)
- **AI**: Google Gemini (explanation only) + hybrid RAG (BM25 + optional dense
  embeddings + Reciprocal Rank Fusion) over the curated `backend/knowledge/` base.
  The deterministic engine computes every orbital number; Gemini only explains them.
